# Contributing Guidelines

Thank you for your interest in contributing to this project!  
Contributions are **limited** and follow strict rules.

These rules are mainly implemented as a result of the project being one that I use to learn key software development principles, and as such, contributing to the project, whilst great for the project's direction as a usable tool, would limit how much I learn.

---

## Contribution Policy

### Contribution Access Is Restricted
This project is primarily developed and maintained by the main developer.  
As such, **not all issues or features are open for community contribution**.

Only issues that are explicitly tagged as:

**`community-approved`**  
(or a similar tag such as `good-first-contribution`, `help-wanted`, etc.)

are available for external contributors to work on.

If an issue does **not** have this tag, it is **not open** for contribution unless the main developer states otherwise.

---

## How to Contribute

### Check for Approved Issues
Before contributing, please verify that the issue you want to work on has the **community-approved** tag.

If it does not, please refrain from submitting a PR unless you have received explicit permission.

### Requesting Permission
If you believe an untagged issue should be open for contribution, you may:
- Comment on the issue requesting approval  
- Wait for the main developer to assign the appropriate tag  

No work should begin until approval is given, this is to prevent both your work and time being wasted.

### Submitting Pull Requests
For approved issues:
- Reference the issue number in your PR  
- Follow the project’s coding style and structure  
- Keep PRs focused and minimal unless otherwise instructed  

---

## Enforcement
The main developer reserves full discretion to:
- Close PRs that do not follow these guidelines  
- Reject contributions to unapproved issues  
- Modify or revoke contribution permissions at any time  

This ensures the project remains aligned with its intended design and roadmap.

---

## Thank You
Your interest and willingness to contribute is appreciated, even within a limited contribution model.  
Approved issues are always welcome, and thoughtful collaboration is encouraged.
